## 세 가지가 B1 과 결정적으로 다르다

### 1. 절단 완전 성공이 0이다

26지점을 시도해 **하나도 완전히 성공하지 못했다.** B1 은 12지점 중 1이었다. 경계 사례가 하나 있다(`RCR-22`/`RCR-23` 분리) — `the affected unit` 의 상황 지시 정관사를 관대하게 읽으면 1이 된다. **즉 완전 성공은 0 또는 1이며 판정 기준에 달렸다.**

### 2. 차단 방향이 압도적으로 `역` 이다

**21 / 26 = 81%.** `정` 은 5건뿐이다 — `RCR-09`(절차 순서) `RCR-13`(차단 분류) `RCR-23`(차단 유지) `RCR-33`(mutation·commit·push 게이트) `RCR-39`(lifecycle 준수).

이것이 이 파일의 가장 큰 관측이다. **라우팅·메타 성격의 규칙은 대부분 「차단 주장을 막는」 방향이다.** 설계에 `역` 축이 없으면 이 파일은 차단 조각의 5분의 4가 처리 불가 상태로 들어간다.

역 21건 중 **강등 대상과 겹치는 것이 15건**이다. `F-3` 이 지목한 「두 경로로 동시에 권위를 잃는」 겹침이 B1 에서 5건이었는데 여기서는 **15건**이다.

## 미정의 용어

정의된 것은 **2개**다 — `conflict-isolated`(15행, `means` 로 12항 연언 정의) · `conflict-unit-blocking`(16행, 부정 정의이나 `D3` 로 범위 미확정).

미정의는 **50개 이상**이다. 그중 판정에 직접 걸리는 것:

- **`compatible active states`**(22행) — 이 파일의 **유일한 차단 해제 조건인데 판정 기준이 없다.** 문면이 차단을 걸고 해제 기준은 제공하지 않는다
- `canonical-ready` · `commit-ready`(17행) — `snippets/` 전역에서 이 파일 17행에만 존재하고 어느 규칙도 정의하지 않는다
- `conflict-isolated` 의 **12개 구성항 전부** — `blocked output` `state` `assumption` `invariant` `owner contract` `validator` `transaction or commit boundary` `acceptance gate` `coherence unit` `evidence` `acceptance` `status`
- `compliant path`(5) / `compliant branch`(10) / `compliant alternatives`(26) / `compliant rescope`(31) — 4개 어휘가 같은 것인지 다른 것인지 문면이 말하지 않는다
- `tier` / `same tier`(19·21) — `snippets/rules/README.md` 의 `tier` 는 **배포 tier** 이고 21행의 것은 **권위 tier** 다. 게다가 README 는 trigger gate 가 로드하지 않으므로 **차용하면 오해석이 된다**

## `|S| ≥ 2` 가 이 파일에서 필터로 작동하지 않는다

표면적으로 합성 후보 26건 **전부**가 슬롯 2 이상이다. B1 은 19건 중 8건이 불충족이었다 — **정반대다.**

이유는 슬롯이 채워져서가 아니다. **이 파일의 거의 모든 차단 문장이 열거를 달고 있어서 열거항이 슬롯으로 세어지기 때문이다.** 슬롯 95개 중 64개가 문면에 존재하지 않는 자리인데도 임계값은 통과한다.

**`|S| ≥ 2` 는 「참조 대상이 실제로 있는가」가 아니라 「이름이 몇 개 나열됐는가」를 세고 있다.**

(문서 자기지시 `this rule` / `It` 을 슬롯으로 세지 않으면 `RCR-42` 가 `|S| = 1` 로 떨어져 불충족 1건이 된다.)
