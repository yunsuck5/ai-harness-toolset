# 종결 판정

B5 의 산출물이다. 설계가 정한 종결 기준에 대해 **닫히는가**를 판정한다.

## 기준

> **현존 규칙이 모두 평가 대상에 올라가고, 그 모든 규칙에 결과와 목표를 동일한 기준으로 적용한다.**
>
> 이 기준은 **열거 가능하고 확인 가능하다.** 규칙을 세고, 각각에 대해 4동작(추가·수정·삭제·재개) 채널이 정의됐는지 확인하고, 전부 예면 닫힌다.

두 조건이다. **① 전부 평가 대상에 올랐는가 ② 각각에 4동작 채널이 있는가.**

## 조건 ① — 전부 평가 대상에 올랐는가 · **예**

`_work/rule-surface-inventory.md` 가 **36개 표면**을 전수 열거하고 각각의 4동작 채널을 문면 근거와 함께 판정했다.

| tier | 수 |
|---|---|
| repo-only `rules/` | 14 |
| 배포 `snippets/rules/` | 5 |
| bootstrap | 2 |
| 루트 instruction (규범 절 6) | 1 |
| 그 밖의 규범 소유 주장 | 9 |

**로드맵의 「규칙 표면 24」와 다르다.** 이 조사는 자기 문면에서 규범 소유를 주장하는 것을 전부 셌고 checklist·template·skill·`CONTRIBUTING.md` 를 포함했다. **더 많이 셌으므로 ①은 충족된다.**

## 조건 ② — 각각에 4동작 채널이 있는가 · **아니오**

### 현재 상태 (설계 적용 전)

| 동작 | 자기 채널을 가진 표면 |
|---|---|
| 추가 | **2 / 36** |
| 수정 | **2 / 36** |
| **삭제** | **0 / 36** (조항 삭제 1, 규칙 삭제 0) |
| 재개 | **0 / 36** (부분 다수, 타 규칙에 대한 정면 채널화 1) |

자기 채널을 가진 둘은 `rules/rule-authority.md` 와 `rules/terminology-glossary.md` 다. 나머지 34개는 4동작이 전부 없거나 **다른 표면이 대신 정의**한다(14쌍 확인).

git 이력 대조 — 규칙 표면 관련 커밋 64건 중 **삭제 0건**, 이름변경 1건. 로드맵의 「삭제 이력 0건」이 재확인됐고, **문면상으로도 경로가 없다**는 것이 추가로 확인됐다.

### 설계를 적용한 표면은 어떻게 되는가

`rules/rule-authority.md` 한 본에 설계를 완주했다(B1). 그 결과 4동작이 이렇게 된다.

| 동작 | 적용 전 | 적용 후 | 무엇이 채웠나 |
|---|---|---|---|
| 추가 | 정의됨 | **정의됨** | 새 원소·합성을 만들고 INDEX 에서 발번한다 |
| 수정 | 정의됨 (목적지 불명) | **정의됨** | key 유지 · 정본 수정 · `refs⁻¹` 전수 검사. 목적지가 `rule_graph/INDEX.md` → 정본 경로로 확정된다 |
| **삭제** | 「제거」가 선택지로만 열거 | **정의됨** | **key 반납.** INDEX 상태를 `반납됨` 으로 바꾸고 `refs⁻¹` 전수를 검사한다. 행을 지우지 않아 재사용 금지가 유지된다 |
| 재개 | 부분 | **부분** | 차단 시점에 무엇이 막았는지가 key 로 나오고, 쿡북의 「개정 진입점」 표가 목적지를 준다. 다만 **막힌 작업을 다시 진행시키는 조건**은 여전히 사용자 결정이다 |

**삭제 채널이 실제로 생겼다.** 이것이 이 트랙의 실질 성과다.

설계가 겨냥한 기전은 정확했다 — 실측상 규칙 파일 삭제 이력이 0건인데 축소는 전부 「파일 내 내용 제거」로 일어났다. **삭제 채널이 정의되지 않아 수정 채널로 우회된 것**이고, 원소 단위로 key 가 걸리면 내용을 지우는 순간 반납이 강제되므로 그 우회가 닫힌다.

### 그런데 ②는 충족되지 않는다

기준이 요구하는 것은 *"**모든** 규칙에 동일한 기준으로 적용"* 이다.

| 표면 | 설계 적용 상태 |
|---|---|
| `rules/rule-authority.md` | **완주** (B1) |
| `snippets/rules/rule-conflict-and-revision-routing.md` | **표본 1개 절** (B2). 파일은 미전환 |
| 나머지 34개 | **미적용** |

`rules/docs-working-model/docs-working-model.md` 는 **보류**다(`D-24`). 사유는 두 가지다.

1. **규모** — 저작이 필요한 참조 슬롯 ≈486개(80%). 우회 2건(합성 입도 굵히기 · 미정의 용어를 사본에 남기기)을 검토했고 둘 다 지배적 비용을 건드리지 못한다
2. **자기 개정 순환** — 이 파일이 `## Self-amendment` 로 자기 개정 절차를 정의하며, *"lifecycle/governance self-revision 은 개정 이전 문면이 지배한다"* 고 한다. **분해의 적법성을 분해 대상이 판정한다**

## 판정 — **트랙은 닫히지 않는다**

조건 ①은 충족되고 조건 ②는 충족되지 않는다.

### 무엇이 확인됐는가

**설계는 한 파일에서 성립한다.** `rules/rule-authority.md` 에 적용해 4동작 중 삭제 채널이 실제로 생겼고, 검증기 `V1`·`V2`·`V3` 가 PASS 한다. 트랙의 불변식 1(*"규칙 권위 주체가 신규추가·수정·삭제에 대한 정규채널을 보유한다"*)이 **그 한 파일에 대해서는 성립한다.**

**일률 적용은 성립하지 않는다.** 최대 대상에서 저작 비율 80%가 관측됐고, 그것은 「분해」가 아니라 「재작성」이다.

### 무엇이 트랙을 막는가

| # | 무엇 | 근거 |
|---|---|---|
| 1 | **저작 비율이 규모에 따라 올라간다** | 27행 62% → 42행 67% → 239행 **80%**. 큰 규칙일수록 문면이 압축돼 있어 원자 단위가 문면에 없다 |
| 2 | **방향 축이 설계에 없는데 대상에 따라 주류가 된다** | 역 비율 37% → **81%** → 42%. 거버넌스·라우팅 규칙에서 특히 크다 — 이 트랙이 다루려는 바로 그 종류다 |
| 3 | **강등 기준이 규범 내용을 재지 않는다** | 세 파일 모두 강등 원인 100%가 표기 형식. 규범 내용 부재로 강등된 조각은 **총 0건** |
| 4 | **그래프 밖에 소비자 셋과 공급자 둘이 있다** | 쿡북 · 배포본 · 기록(소비자), 권위 위임 2건(공급자). 설계가 그중 아무것도 다루지 않는다 |
| 5 | **최대 대상이 자기 분해를 자기 문면으로 규율한다** | `docs-working-model.md` `## Self-amendment` |

### 설계 수정 없이는 닫히지 않는 것

`FINDINGS.md` 에서 **우회하지 못했거나 우회가 설계 수정인 것**만 추린다.

| # | 무엇 | 상태 |
|---|---|---|
| `F-2` | 강등이 key 타입 접두사와 충돌 — 접두사로 권위를 알 수 없게 됨 | 부분 우회. 설계 문면 수정 필요 |
| `F-3` `F-17` `F-26` | 방향 축이 설계에 없음. 조각당 단일 값 전제도 깨짐 | 파일럿 한정 우회. 축을 형식에 넣어야 함 |
| `F-4` | 강등 기준이 표기 형식을 잼 | 우회 안 됨 |
| `F-8` `F-13` `F-21` `F-27` | 그래프 밖 소비자·공급자 | **미우회** |
| `F-11` | 쿡북·합성의 물리 관계에 단일한 답이 없음 | tier 별로 갈라 우회. 설계 문면 수정 필요 |
| `F-22` | 합성을 참조하는 사본의 정본이 정의되지 않음 | 부분 우회 |
| `F-23` | `V3` 가 권위를 검사하지 못함. 불변식 4 는 검사되지 않는 선언 | 우회 안 됨 |
| `F-25` | 조판이 운반하는 규범과 개방 집합 선언은 원소로 담기지 않음 | 미우회 |

### 무엇이 성립하는가 — 부정 결론만 남기지 않기 위해

| # | 무엇 | 근거 |
|---|---|---|
| 1 | **key 반납이 삭제 채널을 만든다** | 실측상 0건이던 삭제가 정의된 동작이 됐다 |
| 2 | **`V2`(정본·사본 일치)가 성립하고 싸다** | 사본 45행 전수 대조 일치. 설계가 「비싸다」로 분류한 것과 달리 `V1` 보다 싸다 |
| 3 | **`V1` 이 참조 무결성을 실제로 잡는다** | 산문 속 예시 key 오염을 두 번 잡아냈다(`F-20`) |
| 4 | **배포본이 자립한다** | 사본을 병기하면 adopter 가 규범을 따를 수 있다. 대가는 2.71× |
| 5 | **문장이 실제 입도다** | 세 파일에서 재현. 문장 아래 절단은 38지점 중 완전 성공 1 |

## 이 판정이 확정하지 않는 것

- **설계가 틀렸다고 판정하지 않는다.** 한 파일에서 성립했고, 막히는 지점 다섯이 전부 **설계 수정이 가능한 형태**로 특정됐다
- **저작 비율 80%가 다른 큰 규칙에서도 나오는지** — `docs-working-model.md` 한 건에서만 잰 값이다
- **쿡북 배율 1.1×** — 실제 쿡북을 쓰지 않은 추정값이다
- **보류한 34개 표면에서 새 유형이 나올지** — 확인하지 않았다
