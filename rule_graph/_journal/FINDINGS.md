# 발견 — 설계가 안 되는 지점

이 작업의 설계는 **확정된 정답이 아니라 시험할 가설**이다. 수행하다 안 되는 것이 나올 것이고, **그것을 발견하는 것이 목적**이다.

설계가 틀렸다는 발견은 실패가 아니라 **산출**이다. 숨기거나 되는 것처럼 만들지 않는다.

## 무엇을 기록하는가

로드맵의 각 batch 에 「설계가 틀렸다는 신호」가 적혀 있다. 그것이 관측되면 여기에 쓴다. 그 목록에 없더라도 **설계대로 하려는데 안 되는 것**은 전부 대상이다.

- 원소로 자를 수 없는 문면
- 원소인데 실질적으로 작업을 막는 것 — 설계가 이것을 금지하므로 발견되면 설계와 문면이 충돌한다
- 합성 선언이 원문보다 길어지는 것
- 정본과 사본의 「같음」을 기계가 판정할 수 없는 것
- 순환 참조
- 그 밖에 설계대로 되지 않는 모든 것

## 기록 형식

```markdown
## F-<n> — <한 줄 제목>

- **시점**: <어느 batch / item 에서>
- **무엇이 안 되는가**: <사실. 원문 인용과 함께>
- **설계의 어느 부분이 걸리는가**: <불변식 / 개념 / 절차 중 무엇>
- **우회 시도**: <무엇을 해봤는가. 안 해봤으면 「없음」>
- **결과**: <우회됨 / 우회 안 됨 / 부분 우회 — 무엇이 남았는가>
- **처리**: <진행함 / 해당 batch 를 보류로 둠>
```

## 우회 규칙

1. **기록한다** — 먼저 사실을 남긴다
2. **우회를 시도한다** — 설계를 조금 고쳐서 되는지 본다. 고친 것도 기록한다
3. **우회가 안 되면 그 batch 를 `보류` 로 두고 다음으로 간다.** 멈추지 않는다

「어려워서」 「애매해서」는 발견이 아니다. **무엇이 왜 안 되는지가 구체적으로 적힐 때만** 발견이다.

## 기록

## F-1 — 파일럿 대상 예비 분해에서 설계 결함 4건이 관측됐다

작업 착수 **전**에 수행한 예비 시험 결과다. 실제 분해가 아니라 **분해 가능성만 본** 것이므로, B1 에서 실제로 수행할 때 달라질 수 있다. 다만 아래는 무인 작업이 같은 벽에 다시 부딪히는 비용을 줄이기 위해 미리 남긴다.

- **시점**: B1 착수 전 예비 시험. 대상 `rules/rule-authority.md` (27행) @ `550c352`
- **관측 규모**: 조각 37개 → 원소 후보 14 / 합성 후보 14(선언 단위 13) / 강등 대상 9
- **관측된 입도**: **문장.** 문장 아래로 자르려는 시도 11곳 중 완전 성공 1, 완전 실패 4, 부분 5, 잉여 1. 방해 요인은 한국어 연결어미로 인한 **주어 생략 7건 + 조응 표현 5건**. 차단 조각의 최소 단위는 「조건 + 규범 서술어」 쌍이며 그보다 작은 단위가 없다

### F-1-a 합성 선언이 원문보다 길어진다

- **무엇이 안 되는가**: 합성 선언 13건이 **전부** 원문보다 길다. 배율 1.45×~6.95×, 중앙값 약 2.55×. 선언에 필요한 원소 슬롯 48개 중 **29개가 문면에 존재하지 않아 신규 저작이 필요**하다
- **설계의 어느 부분이 걸리는가**: 4층 구조의 전제 — 쿡북이 얇고 원소가 정본이라는 비용 배분. 원소가 문면에 없으면 저작 비용이 분해 비용을 넘는다
- **우회 시도**: 없음 (예비 시험이므로)
- **결과**: 미확인
- **처리**: B1 에서 실제 수행하며 확인

### F-1-b 강등 판정이 규범 내용이 아니라 표기 형식에 좌우된다

- **무엇이 안 되는가**: 차단 조각 14개 중 6개가 절단 시 자립하지 못해 「권위 없는 원소」로 내려간다. **자립 실패의 원인이 규범 내용이 아니라 주어 생략·조응이라는 문장 작성 방식**이다
- **설계의 어느 부분이 걸리는가**: 「권위 = 의미」 기준. 실제로는 「권위 = 문장이 얼마나 자립적으로 쓰였는가」로 작동한다. 같은 규범을 주어를 채워 다시 쓰면 권위가 생기고, 생략하면 사라진다
- **우회 시도**: 없음
- **결과**: 미확인
- **처리**: B1 에서 확인. 강등 기준을 「자립하는가」가 아니라 「규범 내용이 남는가」로 좁히는 것이 후보이나, 실제 사례 없이 정하지 않는다

### F-1-c 권위 축이 둘이고 서로 매핑되지 않는다

- **무엇이 안 되는가**: 대상 파일이 `Hard gate / Binding / Advisory` **3-tier** 를 정의하고 그 소유를 주장한다. 설계는 `원소 / 합성` **2-tier** 를 넣는다. 문면상 매핑 불가 — 비차단으로 정의된 Advisory 정의 **본문 안에 금지 clause 가 있고**, Hard gate 정의는 그 자체로 원소인데 차단력의 자격 조건이다
- **순환**: **설계가 이 파일에 권위를 갖는지를, 이 파일이 소유 주장하는 권위 분류가 결정한다**
- **설계의 어느 부분이 걸리는가**: `authority(e) = false` / `authority(c) = true` 라는 2치 구조 자체
- **우회 시도**: 없음
- **결과**: 미확인
- **처리**: B1 에서 확인. 파일럿 대상을 이 파일로 고른 이유가 「자기 적용 실증」이었으므로, 이 순환은 예상 범위 안이다

### F-1-d 「막는가」 축이 단방향이다

- **무엇이 안 되는가**: 작업이 아니라 **차단 주장을 막는** 조각(자동 삭제 금지, hard gate 승격 차단 등)이 원소로 분류되면서 **그 무효화 권한까지 함께 잃는다**
- **설계의 어느 부분이 걸리는가**: 「막는가」를 작업 차단 하나로만 본 것. 규칙에는 「A 를 막는다」와 「A 를 막는 것을 막는다」가 둘 다 있는데 설계가 구분하지 않는다
- **우회 시도**: 없음
- **결과**: 미확인
- **처리**: B1 에서 확인

## F-2 — 강등이 key 타입 접두사와 충돌한다

예비 시험에 없던 **새 결함**이다. 설계 문서 안에서 두 조항이 서로를 부정한다. 실제 강등 사례를 만나기 전에, 발번 규율(`D-2`)을 정하려고 강등 시나리오를 따라가다 드러났다.

- **시점**: B1 / item-01-extract. `D-2`(번호 공간) 결정 중
- **무엇이 안 되는가**: 설계는 세 가지를 동시에 요구한다.
  1. *"**타입 접두사는 필수다.** 권위 여부가 타입으로 결정되므로 key 만 보고 차단 가능 여부를 알 수 있어야 한다"* — `DESIGN.md` 「key 표기」
  2. *"강등되면 `authority = false` 가 되어 차단력을 잃는다"* / *"**강등은 삭제가 아니다.** key 는 유지된다"* — `DESIGN.md` 「강등」
  3. *"key 는 생애 동안 불변이다"* — 불변식 2

  합성 `RC-00007` 이 강등되면 `authority = false` 가 된다. 그런데 key 는 `RC-` 로 남는다. 이 시점부터 **`RC-` 접두사를 보고 「차단 가능」이라고 읽으면 틀린다.** 1번이 무너진다. 1번을 지키려고 `RE-` 로 바꾸면 2번(key 유지)과 3번(key 불변)이 무너진다.
- **설계의 어느 부분이 걸리는가**: 「key 표기」의 타입 접두사 근거와 「강등」의 key 유지 조항. 그리고 `authority` 를 **타입에서 파생시킨 것**(`authority(e)=false` / `authority(c)=true`) 자체 — 강등은 authority 를 타입과 독립적으로 바꾸는 연산인데, 형식에는 그럴 자리가 없다
- **우회 시도**: key 는 접두사째 유지하고, `authority` 를 **INDEX 의 독립 필드**로 둔다. 강등은 그 필드를 `false` 로 바꾸는 것으로 표현한다
- **결과**: **부분 우회.** 불변식 2·4와 「강등은 삭제가 아니다」는 지켜진다. 대신 *"key 만 보고 차단 가능 여부를 알 수 있어야 한다"* 가 **깨진다** — 차단 가능 여부를 알려면 INDEX 를 열어야 한다. 즉 접두사는 「원래 어느 층에서 발번됐는가」라는 이력 표기로 격하되고, 권위의 현재 값은 INDEX 만이 안다
- **처리**: 진행함. 우회를 채택하고 `D-2` · `D-6` 에 기록. 불변식 목록 6개에 「접두사로 권위를 안다」가 들어 있지 않으므로, 그것은 불변식이 아니라 표기 근거라고 판단했다. **설계 수정이 필요한 지점이다** — 접두사를 권위 표시로 쓸 수 없다면 `RE`/`RC` 구분의 근거가 절반 사라진다

## F-3 — 「차단을 막는」 조각이 두 경로로 동시에 권위를 잃는다

`F-1-d` 의 재확인이자 확장이다. 예비 시험은 방향이 단방향이라는 것만 지적했다. 실제 추출에서 그것이 `|S| ≥ 2` 규칙과 **겹쳐서** 작동한다는 것이 드러났다.

- **시점**: B1 / item-01-extract
- **무엇이 안 되는가**: 대상 파일에서 **차단 주장 자체를 막는 조각 7개**가 나왔다.

  | 조각 | 원문 | 무엇을 막는가 |
  |---|---|---|
  | `RA-04` | "각 개별 규칙은 계속해서 자체 의미를 소유한다." | 이 파일이 개별 규칙의 의미를 대신 정하는 것 |
  | `RA-08` | "해당 primitive로 소급되지 않는 강한 파생 규칙은 자동 삭제 대상이 아니라 강등 후보다." | 자동 삭제라는 처분 |
  | `RA-14` | "읽지 않았다는 사실은 결함이 아니다." | 미독을 결함으로 삼는 판정 |
  | `RA-18` | "그것만으로 lifecycle hard gate가 되지는 않는다." | diagnostic 의 hard gate 승격 |
  | `RA-19` | "PASS는 해당 diagnostic이 선언한 predicate만 입증한다." | PASS 를 넓은 입증으로 쓰는 것 |
  | `RA-31` | "영구 rubric·registry·scanner·checklist 또는 작업 간 필수 load를 만들지 않는다." | 상시 강제 장치의 신설 |
  | `RA-03` 의 짝 | (`RA-04` 와 한 문장) | — |

  이 중 **5개(`RA-04` `RA-14` `RA-18` `RA-19` `RA-31`)가 참조 슬롯 1개**다. 설계상 `|S| ≥ 2` 를 못 채우는 합성은 별칭이므로 원소로 내려간다. 원소는 차단하지 못한다. 따라서 **이 5개는 무효화 권한을 잃는다.**

  두 경로가 겹친다 — 방향 축이 없어서 한 번, `|S| ≥ 2` 때문에 또 한 번. 어느 하나만 고쳐도 나머지가 남는다.
- **설계의 어느 부분이 걸리는가**: `authority(e) = false` 의 의미. 설계는 「차단 못 함」을 **작업을 막지 못함**으로 읽었는데, 실제로 필요한 것은 「**다른 규칙의 차단 주장을 무효화하지 못함**」과의 구분이다. 그리고 `|S| ≥ 2` 의 근거(*"별칭에 권위를 주면 원소가 우회 경로로 차단력을 얻는다"*)는 방향 `정` 에서만 성립한다 — 방향 `역` 인 단일 조각은 원소에 차단력을 주는 것이 아니라 **차단력을 빼앗는** 것이므로 그 우려가 적용되지 않는다
- **우회 시도**: 두 가지를 검토했다.
  1. 방향 `역` 조각을 다른 원소와 억지로 묶어 `|S| ≥ 2` 를 채운다
  2. `|S| ≥ 2` 를 방향 `정` 에만 적용하고, 방향 `역` 은 슬롯 1개도 합성으로 인정한다
- **결과**: **1번은 실패.** 억지로 묶으면 묶을 원소를 저작해야 하는데(예: `RA-14` 에 「Advisory 는 비차단이다」를 붙이려면 이미 `RA-12` 가 있으므로 중복 참조가 되고, 그 조합은 원문에 없는 주장을 만든다), 그것은 `F-1-a` 의 저작 문제를 늘린다. **2번은 형식상 성립하나 설계 수정이다** — `|S| ≥ 2` 를 방향 조건부로 바꾸는 것이고, 그러려면 방향이 형식에 먼저 들어와야 한다
- **처리**: 진행함. 2번을 파일럿 범위에서 채택하고 `D-7` 에 기록했다. **설계 수정 후보로 남긴다** — 방향 축(`정` / `역`)이 `authority` 2치와 별개로 필요하다는 것이 이 파일럿의 결론이다

## F-4 — 강등 대상 전부의 자립 실패 원인이 표기 형식이었다

`F-1-b` 의 재확인이며, 예비 시험보다 **더 강한 값**이 나왔다.

- **시점**: B1 / item-01-extract
- **무엇이 안 되는가**: 차단하면서 자립하지 않아 강등 대상이 된 조각이 **10개**인데, **10개 전부**의 자립 실패 원인이 주어 생략(7) 또는 조응(3)이다. **규범 내용이 없어서 강등된 조각은 0개다.** 예비 시험은 14개 중 6개였다
- **설계의 어느 부분이 걸리는가**: *"권위는 의미에서 나온다. 그에 맞는 의미를 갖지 못하면 규칙에서 강등된다"* 와 *"분해했을 때 각 조각이 의미를 갖지 못하면 그것은 권위 없는 원소다"*. 실측된 판정은 「의미를 갖는가」가 아니라 **「한국어 문장을 얼마나 자립적으로 썼는가」** 다
- **우회 시도**: `RA-08` 로 확인했다. 원문의 "해당 primitive" 를 "상위 invariant 의 보호 primitive" 로 채우면 자립하고 권위를 얻는다. 규범 내용은 한 글자도 바뀌지 않았다
- **결과**: **우회 안 됨.** 우회가 성공했다는 것이 곧 결함의 증명이다 — **같은 규범이 표기만 바꿔 권위를 얻었다.** 이 기준을 그대로 쓰면 규칙 저자가 주어를 채워 쓰는 것만으로 차단력을 만들 수 있다
- **처리**: 진행함. 파일럿에서는 「자립하는가」 대신 **「주어·조응을 복원한 뒤에도 규범 내용이 남는가」** 를 판정 기준으로 쓰고 `D-8` 에 기록했다. 이 좁힘은 `F-1-b` 가 후보로 제시한 것과 같다. **설계 수정 후보**

## F-5 — 비차단으로 정의된 등급의 정의 본문 안에 차단 조각이 있다

`F-1-c` 의 일부를 실측으로 확인했다.

- **시점**: B1 / item-01-extract
- **무엇이 안 되는가**: 원문 15행 한 줄이 `Advisory` 를 정의하는데, 그 한 줄 안에서 차단 판정이 반대로 갈린다.

  > **Advisory** — 선택적인 비차단 지침이다. correctness evidence가 아니며, 읽지 않았다는 사실은 결함이 아니다. 필수 registry·scanner·load·의례를 만들지 않으며 stale하면 정리할 수 있다.

  - `RA-12` "선택적인 **비차단** 지침이다" → 차단 없음
  - `RA-14` "읽지 않았다는 사실은 결함이 아니다" → 차단 **있음**, 방향 `역`
  - `RA-15` "필수 registry·scanner·load·의례를 만들지 않으며" → 차단 **있음**, 방향 `정`

  즉 **자기를 비차단이라고 선언하는 정의가 두 개의 차단 조각을 포함한다.**
- **설계의 어느 부분이 걸리는가**: 3-tier(`Hard gate` / `Binding` / `Advisory`)와 2-tier(`원소` / `합성`)의 매핑. `Advisory` → `원소` 로 매핑하면 `RA-15` 의 금지가 소실되고, `Advisory` → `합성` 으로 매핑하면 "비차단"이라는 자기 선언과 모순된다
- **우회 시도**: 등급을 **파일 단위가 아니라 조각 단위로** 매핑한다 — `Advisory` 라는 label 은 문단에 붙어 있을 뿐이고, 조각마다 따로 판정한다
- **결과**: **우회됨.** 실제로 이 추출은 그렇게 했고 문제가 생기지 않았다. 근거는 원문 자신이다 — *"권위는 파일 전체나 label이 아니라 clause × scope × enforcement path 단위로 평가한다"*(`RA-05a`). **원문이 이미 조각 단위 평가를 요구하고 있었다**
- **처리**: 진행함. 다만 이것은 **3-tier 축이 조각 단위로 내려가면 등급 label 이 무엇을 뜻하는지가 비어 버린다**는 뜻이기도 하다 — `Advisory` 문단 안의 조각이 차단한다면 그 조각은 무슨 등급인가. `item-03` 에서 쿡북을 쓸 때 다시 부딪힐 지점이다. `F-1-c` 의 **순환**(설계가 이 파일에 권위를 갖는지를 이 파일의 권위 분류가 결정한다) 부분은 아직 확인되지 않았다
