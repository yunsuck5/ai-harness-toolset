# 발견 — 설계가 안 되는 지점

이 작업의 설계는 **확정된 정답이 아니라 시험할 가설**이다. 수행하다 안 되는 것이 나올 것이고, **그것을 발견하는 것이 목적**이다.

설계가 틀렸다는 발견은 실패가 아니라 **산출**이다. 숨기거나 되는 것처럼 만들지 않는다.

## 무엇을 기록하는가

로드맵의 각 batch 에 「설계가 틀렸다는 신호」가 적혀 있다. 그것이 관측되면 여기에 쓴다. 그 목록에 없더라도 **설계대로 하려는데 안 되는 것**은 전부 대상이다.

- 원소로 자를 수 없는 문면
- 원소인데 실질적으로 작업을 막는 것 — 설계가 이것을 금지하므로 발견되면 설계와 문면이 충돌한다
- 합성 선언이 원문보다 길어지는 것
- 정본과 사본의 「같음」을 기계가 판정할 수 없는 것
- 순환 참조
- 그 밖에 설계대로 되지 않는 모든 것

## 기록 형식

```markdown
## F-<n> — <한 줄 제목>

- **시점**: <어느 batch / item 에서>
- **무엇이 안 되는가**: <사실. 원문 인용과 함께>
- **설계의 어느 부분이 걸리는가**: <불변식 / 개념 / 절차 중 무엇>
- **우회 시도**: <무엇을 해봤는가. 안 해봤으면 「없음」>
- **결과**: <우회됨 / 우회 안 됨 / 부분 우회 — 무엇이 남았는가>
- **처리**: <진행함 / 해당 batch 를 보류로 둠>
```

## 우회 규칙

1. **기록한다** — 먼저 사실을 남긴다
2. **우회를 시도한다** — 설계를 조금 고쳐서 되는지 본다. 고친 것도 기록한다
3. **우회가 안 되면 그 batch 를 `보류` 로 두고 다음으로 간다.** 멈추지 않는다

「어려워서」 「애매해서」는 발견이 아니다. **무엇이 왜 안 되는지가 구체적으로 적힐 때만** 발견이다.

## 기록

## F-1 — 파일럿 대상 예비 분해에서 설계 결함 4건이 관측됐다

작업 착수 **전**에 수행한 예비 시험 결과다. 실제 분해가 아니라 **분해 가능성만 본** 것이므로, B1 에서 실제로 수행할 때 달라질 수 있다. 다만 아래는 무인 작업이 같은 벽에 다시 부딪히는 비용을 줄이기 위해 미리 남긴다.

- **시점**: B1 착수 전 예비 시험. 대상 `rules/rule-authority.md` (27행) @ `550c352`
- **관측 규모**: 조각 37개 → 원소 후보 14 / 합성 후보 14(선언 단위 13) / 강등 대상 9
- **관측된 입도**: **문장.** 문장 아래로 자르려는 시도 11곳 중 완전 성공 1, 완전 실패 4, 부분 5, 잉여 1. 방해 요인은 한국어 연결어미로 인한 **주어 생략 7건 + 조응 표현 5건**. 차단 조각의 최소 단위는 「조건 + 규범 서술어」 쌍이며 그보다 작은 단위가 없다

### F-1-a 합성 선언이 원문보다 길어진다

- **무엇이 안 되는가**: 합성 선언 13건이 **전부** 원문보다 길다. 배율 1.45×~6.95×, 중앙값 약 2.55×. 선언에 필요한 원소 슬롯 48개 중 **29개가 문면에 존재하지 않아 신규 저작이 필요**하다
- **설계의 어느 부분이 걸리는가**: 4층 구조의 전제 — 쿡북이 얇고 원소가 정본이라는 비용 배분. 원소가 문면에 없으면 저작 비용이 분해 비용을 넘는다
- **우회 시도**: 없음 (예비 시험이므로)
- **결과**: 미확인
- **처리**: B1 에서 실제 수행하며 확인

### F-1-b 강등 판정이 규범 내용이 아니라 표기 형식에 좌우된다

- **무엇이 안 되는가**: 차단 조각 14개 중 6개가 절단 시 자립하지 못해 「권위 없는 원소」로 내려간다. **자립 실패의 원인이 규범 내용이 아니라 주어 생략·조응이라는 문장 작성 방식**이다
- **설계의 어느 부분이 걸리는가**: 「권위 = 의미」 기준. 실제로는 「권위 = 문장이 얼마나 자립적으로 쓰였는가」로 작동한다. 같은 규범을 주어를 채워 다시 쓰면 권위가 생기고, 생략하면 사라진다
- **우회 시도**: 없음
- **결과**: 미확인
- **처리**: B1 에서 확인. 강등 기준을 「자립하는가」가 아니라 「규범 내용이 남는가」로 좁히는 것이 후보이나, 실제 사례 없이 정하지 않는다

### F-1-c 권위 축이 둘이고 서로 매핑되지 않는다

- **무엇이 안 되는가**: 대상 파일이 `Hard gate / Binding / Advisory` **3-tier** 를 정의하고 그 소유를 주장한다. 설계는 `원소 / 합성` **2-tier** 를 넣는다. 문면상 매핑 불가 — 비차단으로 정의된 Advisory 정의 **본문 안에 금지 clause 가 있고**, Hard gate 정의는 그 자체로 원소인데 차단력의 자격 조건이다
- **순환**: **설계가 이 파일에 권위를 갖는지를, 이 파일이 소유 주장하는 권위 분류가 결정한다**
- **설계의 어느 부분이 걸리는가**: `authority(e) = false` / `authority(c) = true` 라는 2치 구조 자체
- **우회 시도**: 없음
- **결과**: 미확인
- **처리**: B1 에서 확인. 파일럿 대상을 이 파일로 고른 이유가 「자기 적용 실증」이었으므로, 이 순환은 예상 범위 안이다

### F-1-d 「막는가」 축이 단방향이다

- **무엇이 안 되는가**: 작업이 아니라 **차단 주장을 막는** 조각(자동 삭제 금지, hard gate 승격 차단 등)이 원소로 분류되면서 **그 무효화 권한까지 함께 잃는다**
- **설계의 어느 부분이 걸리는가**: 「막는가」를 작업 차단 하나로만 본 것. 규칙에는 「A 를 막는다」와 「A 를 막는 것을 막는다」가 둘 다 있는데 설계가 구분하지 않는다
- **우회 시도**: 없음
- **결과**: 미확인
- **처리**: B1 에서 확인
